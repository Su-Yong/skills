# Feature Planner 저장 문서 양식

아래 두 양식을 서로 다른 파일에 사용한다. 제목과 내용은 기획 대상에 맞게 바꾸되 원문과 구체적인 구현 조건을 생략하지 않는다. 문서를 채우기 위해 미정 사항을 결정하거나 질문을 미루지 않는다. 필수 운영 규칙과 동일한 양식은 `SKILL.md` 안에도 모두 포함되어 있다.

## 진행 중 질답 기록

```markdown
# <기획 이름> 질답 기록

목표: <현재 사용자가 설명한 목표>
상태: <진행 중 / 중단 / 종료>

## 회차 1

### 에이전트 응답

<실제로 제시한 임시 결정, 질문 번호·설명·선택지를 원문 그대로 저장>

### 사용자 답변

<번호뿐 아니라 추가 조건과 정정도 포함한 사용자 답변 원문>

### 변경 또는 미정 사항

<있는 경우에만: 대체된 결정과 변경 내용, 미답변·건너뜀·보류·충돌>

## 회차 2

<새 질답과 자체 결정을 같은 방식으로 누적>
```

회차는 읽기 위한 구분이다. 질문 번호·상세 설명·모든 선택지·답변과 임시 결정의 원문을 누적한다. 목표, 이유, 확인한 사실과 출처, 정정·추가 조건·미답변 등의 맥락을 보존한다. 매 회차 목표나 전체 요약을 다시 작성할 필요는 없다. 질문 번호와 임시 결정 알파벳은 회차·세션이 바뀌어도 이어진다.

사용자가 이전 결정을 바꾸면 이전 원문을 보존하고 무엇이 대체되었는지 덧붙인다. 변경 또는 미정 사항은 있는 경우에만 작성한다. 별도의 다음 논의 지점이나 고정 후속 질문 목록은 필수 항목이 아니다.

## 종료 시 최종 기획서

```markdown
# <기획 이름> 구현 계획

## 목표

<무엇을 누구를 위해 만들고 어떤 결과를 얻으려는지>

## 핵심 동작

<확정된 동작과 주요 조건·예외, 선택한 구현 방식>

## 구현 할 일

- [ ] <구체적인 구현 작업>
  - 동작과 조건: <사용자·입력·처리·결과와 반드시 지킬 조건>
  - 구현 위치: <확인한 파일·함수 또는 신규로 제안하는 위치임을 명시>
  - 순서와 의존성: <먼저 필요한 작업이나 자료가 있는 경우>
  - 완료 기준: <동작이 맞는지 확인할 수 있는 결과 또는 검증 조건>

## 미결정 사항과 남은 가정

<남은 항목과 영향, 사용자 결정인지 에이전트의 임시 가정인지 구분>
<없으면 없음으로 표시>
```

명시적 종료 시 기존 원문 기록과 별도로 작성한다. 작업 제목은 구체적인 행동을 드러내고 본문에는 결정된 조건·예외·완료 기준을 직접 담는다. 질문 번호나 외부 기록 참조만으로 대신하지 않는다. 확인하지 않은 파일은 확인한 위치처럼 쓰지 않으며 신규 구조는 제안임을 표시한다. 미정 사항과 임시 가정은 영향과 함께 남긴다.
