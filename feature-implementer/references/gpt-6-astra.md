# GPT-6 Astra behavioral corrections

Apply only when selected by `SKILL.md`. Use these adjustments within the common
execution workflow and its protocol, not as extra phases or alternative gates.
Preserve all three core values: plan fidelity, fast implementation through active
parallel work, and human-readable code.

## A1. Carry authorized implementation through to evidence

After the required intake and baseline, perform the mapped local edits and
proportionate validation without asking again whether to begin each step. Use the
common missing-contract rule for real product decisions; continue independent
authorized units instead of pausing the whole task. Do not stop at proposing work
that the user has already asked you to implement. Reversible work is not
automatically in scope, and persistence does not expand authorization
or bypass the finite worker-recovery sequence.

## A3. Keep the integrated report compact but complete

Lead with the actual outcome and use the common integrated report structure. Remove
repeated narration, stock introductions, and decorative formatting; retain all
required fields, requirement-to-evidence links, changed-file reasons, skipped-check
consequences, baseline/regression distinctions, code readability review, and the
authorization boundary. For delegated work, retain shared contracts, parallel
assignments, and actual reasons for direct or sequential work; distinguish
implementation prerequisites from integration and validation prerequisites.
A short report must still explain exactly what is verified and what is not.

## A4. Act on useful delegation through the existing work graph

Actively find units that permitted subagents can implement concurrently, including
producers and consumers whose inputs, outputs, and behavior can be agreed before
implementation. A runtime chain such as A → B → C does not require sequential code
writing. Share the same boundary contract, revision, owner, and local code patterns
with each affected worker; separate implementation prerequisites from the real
outputs needed for integration and validation. Only minimal shared declarations,
overlapping writes, or required observations need sequential work.

Dispatch ready units as capacity becomes available instead of waiting for an
unrelated wave to finish. Size the worker set to useful, write-disjoint work and
available capacity, while the primary handles contracts, bottlenecks, inspection,
and disjoint local work. Record the actual coordination cost or constraint when a
unit stays direct or sequential. Read the full protocol whenever its loading
conditions apply; use its Work Unit contract, exclusive ownership, contract-change
coordination, primary integration, and finite recovery rules. Do not add a worker
quota or accept worker success without inspecting actual changes and evidence.
Missing collaboration tools alone do not block safe direct work.

## A5. Close integration evidence gaps

Before reporting completion, compare actual changes with every active requirement,
its scope and constraints, and check that evidence still covers each required
criterion after integration. Test fixtures or stubs do not prove that real
producers and consumers satisfy their agreed contract. Reuse valid checks and add
checks for uncovered real execution paths or invalidated results; required plan
and repository checks remain part of coverage.

Review actual code for consistent names, declaration structure, control flow, and
grouping by concern. Resolve readability issues in the changed and necessary
integration scope; avoid forced abstractions or unrelated cleanup. Add comments
only for non-obvious reasons and constraints behind hacky or tricky code, after
improving ordinary names and structure. Formatting or passing tests do not replace
this review. Apply common blocked/unverified outcomes when evidence is unavailable;
speed does not excuse unresolved plan mismatches or readability problems.
