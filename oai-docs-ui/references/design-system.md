# OAI Docs UI — 공통 디자인 시스템

두 스킬은 `oai-docs-ui.lib.pen`에서 가져온 같은 컴포넌트·색상·서체를 사용한다. docs는 A4 읽기 문서, ppt는 16:9 발표 자료다. 크기·그리드·정보 밀도만 각 판형에 맞춘다. 사용자 원고의 관계에 따라 필요한 구성을 고르며 12군 전체를 매번 채우지 않는다. 원고·개별 키 컬러·배치는 연결된 일반 `.pen` 작업 파일에 저장한다.

## 시각 원칙과 공통 형태

흰 바탕, 큰 검정 제목, 왼쪽 정렬, 넓고 일관된 여백, 얇은 구분선, 필요한 곳의 연한 색면을 사용한다. 기본 모서리는 0, 그림자는 없다. 일반 본문을 모두 카드로 나누지 않는다. 한 화면의 주요 강조는 1–2곳을 우선하고 그룹 내부 간격을 그룹 외부 간격보다 좁게 둔다.

새 텍스트는 한글·영문·숫자·도표 라벨까지 Pretendard다. `assets/fonts/`의 Regular 400·Medium 500·SemiBold 600·Bold 700을 실제로 연결한다. 폰트 파일을 동봉한 것과 앱에서 해당 폰트로 렌더링하는 것은 별개이므로 한글·영문·숫자 샘플과 실제 굵기를 확인한다. 제공받은 로고·사진·보존 대상 화면은 본래 색과 글자를 유지한다.

## 색상 토큰

`KEY_COLOR`는 불투명 sRGB `#RRGGBB` 한 값이다. 없을 때만 `#5477C4`를 사용한다. 이름만 받은 색이나 잘못된 HEX는 임의 변환하지 말고 정확한 값을 확인한다. 흰색·검정·회색도 유효하다.

| 토큰 | 기본값 | 역할 |
| --- | --- | --- |
| paper | #FFFFFF | 일반 배경 |
| text | #111111 | 핵심 제목·본문·KPI·표 값 |
| muted | #666666 | 보조 정보·출처·머리말·꼬리말 |
| rule | #C7C7C7 | 장식 구분선·표 가로선 |
| neutral-fill | #F4F4F4 | 무채색 자료 면 |
| accent | #5477C4 | 입력 키 컬러·표지 |
| accent-soft | #F5F7FB | 장 도입·설명 상자·절차 페이지 |
| accent-tint | #EAEFF8 | 인용·KPI·강조 면 |
| accent-mid | #CFD9EE | 보조 데이터 면 |
| accent-ink | #4A68A9 | 작은 색상 라벨·밑줄 링크 |
| data-strong | #5477C4 | 중요한 차트 선·점·경계 |
| on-accent | #000000 | accent 위에 글자가 꼭 필요할 때 |

색을 바꿀 때 [팔레트 계산기](../scripts/palette.mjs)를 실행하고 반환된 토큰을 일반 작업 `.pen`의 변수와 해당 인스턴스에 함께 반영한다. 공유 `.lib.pen`의 기본 팔레트를 작업별로 수정하지 않는다. 라이브러리 변수와 작업 변수의 적용은 [구성과 수정](pen-workflow.md#구성과-수정)을 따른다. 셸에서는 패키지 루트를 실제 위치로 정한 뒤 다음처럼 실행한다.

```sh
node "$OAI_PACKAGE_ROOT/scripts/palette.mjs" '#138A72'
```

계산 정의: 채널별 `mix(A,B,w)=floor(A*w+B*(1-w)+0.5)`의 불투명 sRGB를 사용한다. soft/tint/mid는 키 컬러와 흰색을 6%/12%/28%로 혼합한다. accent-ink는 키 컬러에 text를 0%, 5%, … 100% 섞어 paper·soft·tint 모두와 4.5:1 이상 대비를 확보한 첫 값이다. data-strong은 흰색과 대비 3:1 이상인 키 컬러, 아니면 accent-ink다. on-accent는 키 컬러와 대비가 더 높은 순수 검정 또는 흰색이다.

대비는 sRGB 채널 `c`를 0–1로 정규화해 `c≤0.04045 ? c/12.92 : ((c+0.055)/1.055)^2.4`로 선형화한 뒤 `L=0.2126R+0.7152G+0.0722B`, `(L밝음+0.05)/(L어두움+0.05)`로 구한다. 대비 계산을 할 수 없으면 accent-ink·data-strong을 text로 하고 accent 위 글자는 생략하며 검사 미수행을 기록한다.

주요 글자와 수치는 text를 기본으로 유지한다. muted도 실제 배경 대비 4.5:1을 확인하며 부족하면 text로 되돌린다. rule을 글자색이나 유일한 의미 전달 선으로 쓰지 않는다. 흰 키 컬러로 색면이 사라지면 rule 테두리를 보완한다. 팁·인용·사례를 다른 색 계열로 구별하지 않고 라벨·위치·구조로 구별한다.

## 재사용할 12개 구성군

작업 파일의 Components에서 가져온 `OAI/` 컴포넌트를 찾는다. MCP로 작업할 때는 현재 라이브러리 별칭·실제 참조 ID와 자식 이름을 읽는다. 아래 OAI 이름은 탐색용이며 라이브러리 파일의 로컬 ID를 그대로 작업 파일에서 사용하지 않는다. 가져온 `format` theme의 `docs`와 `ppt` 위계는 각각 [A4](docs-layout.md), [16:9](ppt-layout.md)를 따른다. theme 키도 `B:format`처럼 해당 작업의 실제 별칭을 포함한다.

| 구성군 | 찾을 컴포넌트 | 선택·조합 규칙 |
| --- | --- | --- |
| 1. 머리말·꼬리말 | OAI/Header, OAI/Footer | 현재 절과 쪽수·짧은 제목. 표지는 쪽수 생략 |
| 2. 제목·본문 | OAI/Heading, OAI/Body | 탐색 정보·주제명·부제·본문을 서로 다른 위계로 구분 |
| 3. 목차 | OAI/Contents row | 실제 절 제목·최종 쪽수. 필요할 때만 사용 |
| 4. 번호형 핵심 요약 | OAI/Key finding | 핵심 문장과 근거. 번호는 순위가 아닌 탐색 순서 |
| 5. 설명 상자 | OAI/Callout | 정의·팁·제약의 실제 내용. soft 면, 라벨과 설명 |
| 6. 인용 | OAI/Quote | 정확한 인용과 실제 출처를 함께 유지. tint 면 |
| 7. KPI | OAI/KPI | 값·단위·기간·분모·출처. tint 면의 2–3개 연속 셀, 길면 열 감소 |
| 8. 비교 | OAI/Comparison | 같은 기준과 순서로 두 대상을 대조. 긴 내용은 세로 배열 |
| 9. 표 | OAI/Table | 헤더·행 가로선, 문자 왼쪽·숫자 오른쪽 정렬. 긴 표는 헤더 반복 |
| 10. 차트 | OAI/Bar chart, OAI/Line chart | 실제 데이터와 축·단위·기간·출처. 길이와 좌표를 값으로 계산 |
| 11. 절차·로드맵 | OAI/Roadmap | 순서와 실제 시간축 구별. 현재 단계는 라벨·경계로 함께 표시 |
| 12. 출처·주석 | OAI/Source | 연결 번호·설명·실제 출처. 그림·표·인용과 연결을 보존 |

라이브러리 안의 예시 프레임 `Docs / 01 Cover`, `Docs / 02 Chapter`, `Docs / 03 Body` 및 `PPT / 01 Cover`, `PPT / 02 Chapter`, `PPT / 03 Body`를 판형 조합의 참고로 사용한다. 예시 페이지는 컴포넌트 목록과 별개이며, 가져온 라이브러리를 연결한 작업 파일에서 해당 판형의 페이지를 구성한다. 예시의 내용·통계·출처는 실제 제작 원고를 대신하지 않는다. 일부만 변경해 이전 샘플 문구가 결과에 남지 않도록 모든 텍스트를 검토한다.

## 데이터와 근거

- 막대는 0에서 시작한다. 음수는 0 기준 양쪽에 그린다. 결측을 0으로 바꾸지 않는다. 의미 있는 범주 순서는 보존한다.
- 선 차트의 x좌표는 실제 경과 시간에 비례한다. 결측에서는 선을 끊고, 예측·보간·축 0 생략·로그축은 표시한다. 실제 값을 임의 평활화하지 않는다.
- 차트 점·막대 길이·표시 값·축 범위·단위·기간·분모를 원자료와 대조한다. 같은 비교의 축 범위는 같게 둔다. 색 외에도 직접 라벨·마커·선 모양을 사용한다.
- 표의 빈 값·미제공·해당 없음은 0과 구분한다. 넓은 표는 식별 열을 반복한 여러 표로 나눈다. 비교 기준이 다르면 차이를 밝힌다.
- 날짜 없는 로드맵에는 기간·진행률을 추정해 넣지 않는다. 참조 출처의 저자·연도·제목·링크도 모르면 만들지 않는다.
- 텍스트·표·차트는 편집 가능한 노드로 유지한다. 그림으로 변환한 페이지나 숫자처럼 보이는 장식 도형으로 대체하지 않는다.

## 표지 이미지

새 표지는 [동봉 생성기](../scripts/generate-cover.mjs)로 키 컬러와 함께 만든다. Node.js 20 이상이 필요하며 코드·셰이더는 패키지에 들어 있다. 실행 파일 경로와 출력 경로를 실제 패키지 위치에서 해석한다. 작업·버전에 맞는 고유한 기본 이름을 `OAI_COVER_BASENAME`에 정하고, 해당 PNG와 JSON이 모두 없는지 확인한다. 기존 표지나 이전 작업 결과를 덮어쓰지 않는다. 생성기는 파일이 이미 있으면 실패하므로 재실행·재채색에도 새 이름을 사용한다.

```sh
node "$OAI_PACKAGE_ROOT/scripts/generate-cover.mjs" --random --color '#5477C4' --out "$OAI_PACKAGE_ROOT/assets/${OAI_COVER_BASENAME:?고유한 출력 이름을 먼저 지정하세요}.png"
```

기본 출력은 2600×1200 PNG, 비율 13:6이다. docs의 이미지 프레임은 13:6으로 유지하고 최종 크롭 뒤 최소 2184×1008을 확보한다. ppt는 가로 판형에 맞는 더 넓은 프레임에 비례 확대 후 크롭할 수 있으며, 예시는 1680×352 프레임이다. 어느 모드에서도 가로·세로를 따로 늘리지 않는다. 사용자 색을 기본 예시 색 대신 전달한다. 고정 생성 요청은 `--random none`과 seed·스타일·설정을 지정하며, 옵션은 [파라미터 문서](../scripts/shader-parameters.md)를 확인한다. PNG와 같은 이름의 JSON에 seed·레이어·파라미터·시간·색을 보존한다. 색만 바꿀 때는 형태·seed·크기를 유지하고 키 컬러만 바꾸되 출력 이름은 새로 정한다.

제목·부제·날짜는 이미지 밖의 Pretendard 텍스트로 둔다. 이미지에 글자·로고·편집 UI를 합성하지 않는다. 가로세로를 따로 늘리지 말고 비율에 맞춰 크롭한다. 밝은 키 컬러의 중성 보정은 생성 JSON의 `neutralFallback` 기록으로 확인한다. 생성 실패를 다른 스타일 이미지로 조용히 대체하지 않고 원인을 해결한다. 원본 코드·라이선스는 [vendor NOTICE](../scripts/vendor/NOTICE.md), 폰트 라이선스는 [LICENSE.txt](../assets/fonts/LICENSE.txt)에 있다. 셰이더 모음에는 CC BY-NC-SA 등을 포함한 서로 다른 라이선스가 있으므로 전체를 하나의 MIT 자산으로 표시하지 않고 선택한 스타일의 고지를 유지한다.

## 디자인 출처 기록

이 패키지는 기존 통합 명세의 A4·Pretendard·단일 키 컬러 규칙을 채택했다. 수치와 판형은 통합 체계의 결정이며 원본 PDF를 그대로 실측·복제한 값이 아니다. 아래는 기존 컴포넌트 지침에 기록된 구조 출처다. 원본 PDF는 재사용 실행에 필요하지 않으며 원본의 로고·통계·본문을 새 원고에 복제하지 않는다.

16:9 그리드·발표 글자 크기는 같은 시각 원칙을 발표 목적에 맞춰 확장한 제작 규격이다.
