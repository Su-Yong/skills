# create-ui

데이터 포맷을 먼저 정의하고 페이지의 깊이와 계층을 설계한 뒤, 필요한 정보만 담은 웹사이트를 만드는 스킬입니다. Vite·React·Tailwind CSS·shadcn/ui를 사용하고, 필요한 서버는 Hono + Node로 구성합니다.

[실행 지침](SKILL.md) · [스타일 적용법](reference/style-system.md) · [스타일 자산](assets/styles.css)

## 사용 방법

스킬을 사용할 수 있는 에이전트 환경에서 대상 프로젝트를 열고 채팅으로 요청합니다. 아래 명령은 스킬에 전달하는 요청이며 별도 셸 프로그램을 설치하지 않습니다.

```text
$create-ui
팀의 장비 목록과 장비별 상세 페이지를 만들어 줘.
장비 데이터를 먼저 정의하고, DB 없이 조회할 수 있게 해 줘.
```

| 요청 | 동작 |
| --- | --- |
| `$create-ui <제작 요청>` | 데이터·페이지 구조를 정하고 UI와 필요한 API·저장 기능을 구현합니다. |
| `$create-ui migrate` | 기존 기능과 데이터 계약을 보존하며 기술과 화면 구성을 전환합니다. 기존 서버가 있으면 교체 여부를 묻습니다. |
| `$create-ui style` | 현재 프로젝트의 스타일과 변경 가능한 항목을 짧게 보여줍니다. 파일을 수정하거나 미리보기 앱을 만들지 않습니다. |
| `$create-ui style <변경 요청>` | 색상·글꼴·간격부터 페이지 계층과 탐색 방식까지 현재 프로젝트에서 수정합니다. |
| `$create-ui help` | 명령과 사용법을 안내합니다. |

상세 동작은 [migrate](reference/commands/migrate.md), [style](reference/commands/style.md), [help](reference/commands/help.md) 문서로 나누어 관리합니다.

```text
$create-ui style 팔레트를 블루로 바꾸고, 표의 행 간격을 조금 좁혀 줘.
```

```text
$create-ui style 프로젝트 아래에 중복된 중간 메뉴를 없애 줘.
목록과 상세는 별도 페이지로 유지하고, 목록의 검색 조건을 보존해 줘.
```

```text
$create-ui migrate
현재 기능과 API 계약을 유지하면서 페이지 구조와 디자인을 바꿔 줘.
기존 서버는 그대로 사용할게.
```

이미 전달한 서버 유지·교체 결정은 다시 묻지 않습니다. 아직 결정하지 않은 기존 서버의 교체 여부는 확인한 뒤 적용합니다.

## 기본 디자인

폰트는 Pretendard를 사용하고, 그 외에는 shadcn/ui 공식 기본 컴포넌트와 중립 테마를 그대로 사용합니다. 글자 크기·행간·간격·높이·모서리·테두리·그림자는 기본 디자인을 따릅니다. 블루·그린·바이올렛·오렌지는 명시적으로 선택할 수 있는 공식 색상 프리셋이며, 테마마다 라이트·다크와 시스템 설정을 지원합니다.

shadcn.io Block은 실제 프리뷰를 확인하고, 데이터 우선순위·도구 모음·반응형 구조가 맞는지 살펴 선택합니다. 원본과 구현 결과를 비교하고 불필요한 정보는 제거합니다. 접근할 수 없거나 적합한 후보가 없으면 이유를 알린 뒤 shadcn/ui 컴포넌트로 구성합니다.

본문뿐 아니라 실제 필요한 Navbar·Sidebar 등 각 영역에 참고 Block을 연결합니다. 공통 Navbar는 한 번 선택해 여러 페이지에서 재사용하며, 불필요한 영역은 추가하지 않습니다.

Select·Button·Input 등은 가능한 한 실제 shadcn/ui 컴포넌트를 역할에 맞게 사용합니다. 전역 테마 전환은 공식 아이콘 메뉴 패턴을 따르고, 필드의 값 선택에는 Select를 사용합니다. 기본 HTML 컨트롤에 스타일만 붙여 대체하지 않습니다. 아이콘은 `lucide-react`의 Lucide 아이콘으로 통일합니다.

상세는 별도 페이지로 열고, 동선은 페이지의 깊이와 계층을 정리해서 줄입니다. 불필요한 설명·장식은 제거하되 사용법을 이해하는 데 필요한 레이블과 오류 피드백은 유지합니다.

중첩 카드는 기본적으로 사용하지 않습니다. 실제 참고한 shadcn.io Block에서 중첩 카드를 확인한 경우에만 필요한 범위에서 허용합니다.

## 프로젝트에 적용하기

스타일을 적용하거나 수정할 때 [스타일 적용법](reference/style-system.md)을 읽습니다. 자산은 현재 프로젝트로 복사하여 사용하며, 이미 적용한 값을 매번 초기화하지 않습니다. 앞서 기획한 커스텀 스타일 수치 대신 shadcn/ui 공식 값을 기본으로 사용하고, 명시적인 `style` 요청만 덮어씁니다.

실제 저장이 필요할 때 SQLite를 우선 검토합니다. DB가 필요 없는 사이트에 DB를 추가하지 않습니다. 새 서버의 기본 구성은 개발 중 Vite와 API를 함께 실행하고, 빌드 후 하나의 Node 서버에서 웹 파일과 API를 제공하는 방식입니다.

테스트 파일·테스트 스위트·별도 검증 스크립트를 만들지 않습니다. 필요한 빌드와 기존 검사, 실제 브라우저에서의 화면·동작 확인을 수행하고 확인하지 못한 항목은 결과에 남깁니다.
