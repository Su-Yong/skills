# migrate

기존 웹사이트의 기능과 데이터 계약을 보존하면서 Vite·React·Tailwind CSS·shadcn/ui 기반으로 기술과 화면을 함께 전환한다. 공통 작업 범위는 [스킬 진입점](../../SKILL.md)을 따른다.

## 호출과 적용 범위

```text
$create-ui migrate
$create-ui migrate 주문 관리 화면부터 전환해 줘.
$create-ui migrate 기존 서버는 유지하고 프런트엔드를 전환해 줘.
```

명시한 전환 범위가 있으면 그 범위부터 작업한다. 좁은 화면 요청을 전체 저장소 교체로 확대하지 않는다. 범위를 별도로 정하지 않았다면 기존 앱의 구성을 확인해 전환 대상을 짧게 설명하고 진행한다. 중요한 기능이나 데이터 처리 방식의 의미가 불명확할 때만 영향을 받는 부분을 질문한다.

## 전환 전에 확인할 내용

- 실행·빌드 명령, 패키지 구성, 기존 변경, 페이지 경로와 메뉴를 확인한다.
- 사용자가 수행하는 주요 조회·입력·저장 흐름과 목록의 검색·필터 상태를 확인한다.
- 기존 API의 요청·응답, 저장 데이터, 인증·권한, 서버 전용 동작을 확인한다. 데이터 포맷을 새로 정리하더라도 기존 계약을 임의로 바꾸지 않는다.
- 현재 적용된 브랜드·스타일과 전환 요청을 비교한다. 명시적 브랜드 지침과 공통 기본값이 충돌하면 해당 선택만 확인한다.

영향받는 현재 코드와 실제 실행 결과를 근거로 전환 대상을 정리한다. 추측한 기존 기능을 사실로 기록하거나 자료 조사만으로 작업을 끝내지 않는다.

## 기존 서버의 유지와 교체

**기존 서버가 있고 이번 작업에서 선택을 받지 않았다면 유지할지 교체할지 질문한다.** 이미 명시한 유지·교체 선택을 다시 승인받지 않는다. 질문의 이유는 기존 서버를 자동으로 교체하지 않는 이 명령의 규칙 때문임을 짧게 설명한다.

| 확인한 상태 | 수행할 작업 |
| --- | --- |
| 서버 없음 | Hono + Node로 구성한다. |
| 기존 서버 유지 선택 | 서버 기능과 계약을 유지하고 새 프런트엔드를 연결한다. 기존 서버를 단일 Node 구성에 맞추려고 다시 작성하지 않는다. |
| 기존 서버 교체 선택 | 필요한 기존 기능을 보존하며 Hono + Node로 전환한다. 이전 서버 전용 기능의 대응을 확인한 뒤 연결한다. |
| 아직 답변 없음 | 서버 교체에 의존하는 변경은 기다리고 데이터·페이지 분석 등 독립적인 작업을 진행한다. 미응답을 교체 승인으로 취급하지 않는다. |

저장소도 필요한 범위에서만 변경한다. DB 교체나 데이터 삭제를 서버 교체에 자동으로 포함하지 않는다. 새로 DB가 필요하면 SQLite를 기본 후보로 검토한다.

## 화면과 코드 전환

1. 데이터 종류와 사용자 작업을 바탕으로 페이지별 데이터·행동·경로를 정리한다. [레이아웃 기준](../layout.md)을 적용해 깊이와 계층을 조정하고, 상세는 별도 페이지로 구성한다.
2. [Block 선택 기준](../blocks.md)에 따라 Navbar·Sidebar 등 필요한 공통 영역과 본문 각각에 실제 shadcn.io 레이아웃을 대응시킨다. 기존 기능을 화면에서 빠뜨리지 않으면서 핵심 정보 관계를 유지해 조정한다.
3. [컴포넌트 기준](../components.md)을 따라 가능한 UI를 실제 shadcn/ui 컴포넌트로 구성한다. Select가 필요한 곳에 모양만 꾸민 네이티브 선택 상자를 대신 넣지 않는다. 아이콘은 Lucide를 사용하고 불필요한 아이콘은 추가하지 않는다.
4. [스타일 체계](../style-system.md)에 따라 shadcn/ui 공식 기본 테마와 컴포넌트 외형을 현재 프로젝트에 적용한다. 임의의 테두리·크기·그림자 재정의는 추가하지 않는다. 기존 프로젝트의 유효한 수정과 요청한 브랜드 값을 보존하며 라이트·다크와 모바일 구성을 함께 맞춘다.
5. 새 코드와 전환 대상 코드는 TypeScript로 작성한다. 프런트엔드·API의 입력과 출력이 연결되는지 확인하고 기존 인증·권한·실패 처리를 유지한다.
6. 새 서버 구성은 개발 중 Vite와 API를 함께 실행하고, 빌드 후 하나의 Node 서버가 웹 파일과 API를 제공하도록 한다. 기존 서버를 유지하는 경우에는 그 환경의 실행 방식을 따른다.

경로 변경 전에는 기존 직접 접근과 외부 연결에 미치는 영향을 확인한다. 기존 접근을 유지할 방법이 불명확하면 그 경로의 변경만 보류한다. 목록으로 돌아왔을 때 검색·필터 등 작업 맥락을 복원하고, 새 상세 경로의 직접 접근과 새로고침도 지원한다.

이전 파일과 의존성은 실제 사용처가 사라졌음을 확인한 범위에서만 정리한다. 사용자의 변경을 덮어쓰거나, 전환하지 않은 기능을 제거해 새 화면을 완성한 것으로 취급하지 않는다.

## 확인과 결과

별도 요청 없이 테스트 파일·테스트 모음·검증 스크립트·테스트 앱을 새로 만들지 않는다. 기존에 있는 관련 검사와 빌드를 실행하고 실제 앱을 브라우저에서 수동 확인한다.

- 전환 전후의 주요 조회·이동·입력·저장 흐름, API 계약과 필요한 영속성을 비교한다.
- 데스크톱·모바일, 라이트·다크, 긴 내용·빈 상태·로딩·오류, 키보드 조작을 확인한다.
- 변경한 경로의 직접 접근과 목록 맥락 복원을 확인한다. API·정적 파일 오류가 페이지 HTML로 덮이지 않는지도 확인한다.

결과에는 전환한 범위, 유지·교체한 서버와 이유, 보존한 계약, 실제 참고한 Block, 실행 방법과 확인 결과를 남긴다. 서버 기능이나 URL 대응을 확인하지 못했다면 그 부분과 영향을 명시하고 완료한 것으로 보고하지 않는다. 전역 설치·배포는 이 명령에 포함되지 않는다.
