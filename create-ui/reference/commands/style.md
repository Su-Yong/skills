# style

현재 프로젝트의 스타일을 확인하거나 자연어 요청에 맞춰 시각적 표현·페이지 계층·탐색 방식을 수정한다. 공통 작업 범위는 [스킬 진입점](../../SKILL.md)을 따른다.

## 조회와 변경 구분

```text
$create-ui style
$create-ui style 팔레트를 블루로 바꾸고 표 간격을 줄여 줘.
$create-ui style 주문 목록과 상세의 중간 페이지를 없애고 메뉴 계층을 정리해 줘.
```

변경 요청이 없는 `style`은 읽기 전용이다. 현재 설정을 안내한 뒤 끝낸다. 파일 생성·설치·서버 시작·미리보기 앱 생성·기술 전환을 실행하지 않는다. 요청이 구체적인 변경을 포함하면 현재 프로젝트의 관련 파일을 수정한다.

## 현재 설정 확인

다음 항목 중 요청과 관련 있는 실제 선언과 사용처를 확인한다.

- 프로젝트의 전역 스타일, CSS 변수, 테마 설정과 로딩 순서
- 적용된 `data-palette`, 라이트·다크·시스템 선택 처리
- 실제 폰트 로딩, 역할별 글자 크기·행간·간격·모서리
- 영향을 받는 페이지와 shadcn/ui 컴포넌트의 변형·지역 재정의
- 구조 변경이라면 페이지 경로, 상하 관계, 메뉴와 목록 상태 보존 방식

조회 결과는 현재 파일과 이미 실행 중인 화면에서 확인한 값으로 설명한다. 스킬 자산의 기본값을 현재 프로젝트에 적용된 값처럼 보고하지 않는다. 변수나 조건부 스타일 때문에 값을 확정할 수 없으면 선언 위치와 확인하지 못한 부분을 밝힌다. 조회를 위해 서버를 새로 시작하지 않는다.

웹 프로젝트나 스타일이 없으면 현재 설정이 없음을 알리고 변경 가능한 항목과 호출 예시를 안내한다. 기본값을 설치해 조회 결과를 만드는 방식으로 처리하지 않는다.

## 변경 요청 처리

| 요청 종류 | 적용할 변경과 읽을 자료 |
| --- | --- |
| 컬러·폰트·글자 크기·여백·모서리·전환 | [스타일 체계](../style-system.md)를 읽고 현재 프로젝트의 실제 토큰과 필요한 지역 스타일을 수정한다. |
| 컨트롤 크기·표현·선택 방식 | [컴포넌트 기준](../components.md)을 읽고 해당 shadcn/ui 컴포넌트의 속성·변형·클래스를 조정한다. |
| 영역 너비·열 수·정보 배치 | [레이아웃 기준](../layout.md)을 읽고 데이터 관계와 주요 행동을 유지하며 배치를 조정한다. 새로운 레이아웃 참고가 필요할 때만 [Block 기준](../blocks.md)을 읽는다. |
| 페이지 깊이·상하 관계·메뉴 | [레이아웃 기준](../layout.md)을 읽고 경로·메뉴·연결을 함께 수정한다. 상세는 별도 페이지를 기본으로 유지한다. |

요청에 필요한 자료만 읽는다. 단순 팔레트 교체를 위해 모든 명령 문서를 읽거나 전체 페이지를 재설계하지 않는다.

1. 변경할 실제 선언과 영향을 받는 화면을 짚고 의도를 짧게 알린다. 일반적인 스타일 변경에 별도 승인 단계를 추가하지 않는다.
2. 프로젝트에 복사된 자산이나 기존 스타일 선언을 수정한다. 설치된 스킬의 자산, 전역 기본값, 다른 프로젝트는 수정하지 않는다. 원본 CSS를 다시 복사해 사용자의 기존 변경을 덮어쓰지 않는다.
3. 라이트·다크를 함께 조정하고 텍스트·컨트롤·포커스가 구분되는지 확인한다. 간격이나 글자 크기를 줄여 중요한 조작을 숨기지 않는다.
4. 변경하는 UI에는 실제 shadcn/ui 컴포넌트를 최대한 활용한다. Select·Button·Input 등 대응 컴포넌트가 있는데 모양만 흉내 낸 네이티브 컨트롤로 대체하지 않는다. 필요한 아이콘은 Lucide로 통일한다.
5. 페이지 구조를 바꾸면 관련 경로와 메뉴를 함께 연결하고 목록의 검색·필터 맥락을 보존한다. Navbar·Sidebar 등 변경하는 공통 영역에도 맞는 Block을 대응시키며 본문 참고만으로 대신하지 않는다. 동선 단축을 상세 옆 패널의 도입으로 대체하지 않는다.

기본 스타일은 설치한 shadcn/ui의 공식 기본값이다. 자체 글자 크기·간격·높이·모서리·테두리·그림자 값으로 기본 외형을 다시 만들지 않는다. 명시적 사용자 요청은 그 기본값보다 우선하며, 요청한 부분만 수정한다. 필요한 데이터·접근성·사용 흐름을 잃게 되는 충돌이 있으면 영향받는 부분만 확인한다. 새로운 사업 기능·데이터 계약·서버 교체는 스타일 변경에 자동으로 포함하지 않는다. 기존 기술과 맞지 않아 넓은 기술 전환이 필요한 경우에도 그 전환을 몰래 실행하지 않는다.

## 확인과 결과

조회만 수행했다면 확인한 설정, 변경 가능한 항목, 읽을 수 없었던 부분을 간단히 보여준다. 수정하지 않은 항목을 수정한 것으로 보고하지 않는다.

변경했다면 기존 빌드와 관련 검사를 필요한 범위에서 실행하고, 실제 화면에서 다음을 수동 확인한다. 별도 요청 없이 테스트 파일·테스트 모음·검증 스크립트·테스트 앱을 만들지 않는다.

- 변경된 화면의 데스크톱·모바일 배치와 라이트·다크
- 선택·입력·저장과 키보드 포커스 등 영향을 받은 조작
- 긴 텍스트·빈 내용·오류에서의 표현과 필요한 정보의 노출
- 구조 변경 시 상세 직접 접근, 메뉴 연결, 목록 상태 복원

결과에는 바뀐 값과 화면, 영향을 받는 파일, 실제 확인한 사항과 남은 한계를 짧게 적는다. 현재 환경에서 확인할 수 없는 동작은 성공으로 간주하지 않는다.
